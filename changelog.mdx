<Update label="November 2026" description="Sort API v2.0.0" tags={["API", "Breaking change"]}>
  ## The Merge Sort API is now the Sort API

  `POST /sort` and `POST /sort/steps` now use quick sort instead of merge sort. Quick sort runs in O(n log n) time on average and O(n^2) in the worst case.

  <Warning>
    Breaking change: each item in the `steps` array from `POST /sort/steps` is now a partition step with `pivot`, `before`, `equal`, and `after`. The `left`, `right`, and `merged` fields are gone.
  </Warning>

  ```json
  { "step": 1, "pivot": 2, "before": [1], "equal": [2], "after": [4, 3] }
  ```

  See [how quick sort works](/merge-sort-api/guides/how-it-works) to read the new steps.

  ### Choose a sort algorithm

  `POST /sort` accepts an optional `algorithm` field: `quick` (default), `merge` (stable), or `heap`. The response echoes `algorithm`. Unknown values return `422`. `POST /sort/steps` always uses `quick`.

  ```bash
  curl -X POST http://localhost:8000/sort \
    -H "Content-Type: application/json" \
    -d '{"numbers": [5, 2, 9, 1], "algorithm": "merge"}'
  ```
</Update>

<Update label="October 2026" description="Calculator API v2" tags={["API"]}>
  ## `POST /v2/calculate`

  A single endpoint that takes an `operation` and two or more `operands`.

  ```bash
  curl -X POST http://localhost:8000/v2/calculate \
    -H "Content-Type: application/json" \
    -d '{"operation": "add", "operands": [1, 2, 3]}'
  ```

  v1 is unchanged and still supported.
</Update>

<Update label="October 2026" description="Todo API" tags={["API", "Deprecation"]}>
  ## `GET /todos/list-all` is deprecated

  Use `GET /todos` with `page` and `page_size` instead. The old endpoint still works but is marked deprecated in the API reference.
</Update>
