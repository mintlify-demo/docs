{user.name ? <>{user.name}, esto es</> : <>Esto es</>} lo que puedes esperar cuando envías listas grandes a `POST /sort`.

| Tamaño de la lista | Tiempo típico | Notas |
| --- | --- | --- |
| 1,000 números | menos de 5 ms | Adecuado para cualquier solicitud |
| 100,000 números | unos 200 ms | Usa `/sort`, no `/sort/steps` |
| 1,000,000 números | de 2 a 3 s | Divide la lista y fusiona tú mismo las partes ordenadas |

## ¿Por qué no usar `/sort/steps` para listas grandes? {#why-not-/sort/steps-for-big-lists}

`/sort/steps` devuelve cada partición, y una lista de *n* números puede producir hasta *n − 1* particiones. Para 100,000 números, eso supone una respuesta de varios megabytes. Úsalo para enseñar y depurar, no para tráfico de producción.

## Memoria {#memory}

Quick sort en la Sort API crea nuevas listas `before`, `equal` y `after` en cada partición, así que necesita memoria adicional proporcional al tamaño de la entrada. La API mantiene toda la lista en memoria, así que mantén cada solicitud por debajo de unos 10 MB de JSON.
