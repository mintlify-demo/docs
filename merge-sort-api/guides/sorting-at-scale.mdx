{user.name ? <>{user.name}, here's</> : <>Here's</>} what to expect when you send large lists to `POST /sort`.

| List size | Typical time | Notes |
| --- | --- | --- |
| 1,000 numbers | under 5 ms | Fine for any request |
| 100,000 numbers | about 200 ms | Send `/sort`, not `/sort/steps` |
| 1,000,000 numbers | 2 to 3 s | Split the list and merge the sorted parts yourself |

## Why not `/sort/steps` for big lists?

`/sort/steps` returns every partition, and a list of *n* numbers can produce up to *n* partition steps. Each step also repeats the `before` and `after` lists, so 100,000 numbers produce a response of many megabytes. Use it for teaching and debugging, not production traffic.

## Memory

The API's quick sort builds new `before`, `equal`, and `after` lists at each partition, so it needs extra memory proportional to the input size. Send `"algorithm": "heap"` to `/sort` if you need constant extra memory. The API holds the whole list in memory, so keep a single request under about 10 MB of JSON.
