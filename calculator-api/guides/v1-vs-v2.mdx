v1 shipped first with one endpoint per operation. v2 added a single, more flexible endpoint. Here is the same job in both.

<Tabs>
  <Tab title="v1: two numbers">
    ```bash
    curl -X POST http://localhost:8000/v1/multiply \
      -H "Content-Type: application/json" \
      -d '{"a": 6, "b": 7}'
    ```

    ```json
    { "result": 42 }
    ```
  </Tab>
  <Tab title="v2: any number of operands">
    ```bash
    curl -X POST http://localhost:8000/v2/calculate \
      -H "Content-Type: application/json" \
      -d '{"operation": "multiply", "operands": [6, 7, 2]}'
    ```

    ```json
    { "result": 84, "operation": "multiply", "operands": [6, 7, 2] }
    ```
  </Tab>
</Tabs>

## Differences

<AccordionGroup>
  <Accordion title="Request shape" defaultOpen>
    v1 sends `{ "a": 6, "b": 7 }`. v2 sends `{ "operation": "multiply", "operands": [6, 7] }`.
  </Accordion>
  <Accordion title="Response shape">
    v1 returns `{ "result": 42 }`. v2 returns the same field and also echoes `operation` and `operands`.
  </Accordion>
  <Accordion title="Operations">
    v1 has `add`, `subtract`, `multiply`, and `divide`. v2 has those four plus `power` and `modulo`. Both apply left to right across `operands`:

    | Operation | Operands | Result |
    | --- | --- | --- |
    | `power` | `[2, 3, 2]` | `(2 ** 3) ** 2 = 64` |
    | `modulo` | `[17, 5]` | `2` |

    ```bash
    curl -X POST http://localhost:8000/v2/calculate \
      -H "Content-Type: application/json" \
      -d '{"operation": "power", "operands": [2, 3, 2]}'
    ```

    ```json
    { "result": 64, "operation": "power", "operands": [2, 3, 2] }
    ```
  </Accordion>
  <Accordion title="Errors">
    The same in both: dividing by zero returns a `400` with a `detail` message. In v2, `modulo` with a `0` divisor also returns a `400`.
  </Accordion>
</AccordionGroup>

<Info>
  A real API would version through a header or a path prefix and keep old versions working. This demo uses the path prefix (`/v1`, `/v2`) and the docs use Mintlify's version switcher, so each version has its own API reference.
</Info>

## Migrating from v1 to v2

Move every v1 call to `POST /v2/calculate` before v1 is removed on January 31, 2027. Each v1 endpoint maps to one `operation` value:

| v1 endpoint | v2 request body |
| --- | --- |
| `POST /v1/add` | `{"operation": "add", "operands": [a, b]}` |
| `POST /v1/subtract` | `{"operation": "subtract", "operands": [a, b]}` |
| `POST /v1/multiply` | `{"operation": "multiply", "operands": [a, b]}` |
| `POST /v1/divide` | `{"operation": "divide", "operands": [a, b]}` |

<Steps>
  <Step title="Change the URL">
    Replace `/v1/<operation>` with `/v2/calculate`.
  </Step>
  <Step title="Change the body">
    Set `operation` to the name from the old path, and put `a` and `b` in order in the `operands` array.

    ```bash
    # Before (v1)
    curl -X POST http://localhost:8000/v1/divide \
      -H "Content-Type: application/json" \
      -d '{"a": 12, "b": 4}'

    # After (v2)
    curl -X POST http://localhost:8000/v2/calculate \
      -H "Content-Type: application/json" \
      -d '{"operation": "divide", "operands": [12, 4]}'
    ```
  </Step>
  <Step title="Read the same result">
    The `result` field works the same way. Both calls above return `"result": 3`. v2 also echoes `operation` and `operands`, and dividing by zero still returns a `400`.
  </Step>
</Steps>
